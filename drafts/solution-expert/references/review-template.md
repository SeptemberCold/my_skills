# 审核助手契约

> 本文件由 `solution-expert` 在 Step 4.2 **按需**读取，**不要**在主 SKILL.md 中整段复述。
>
> 加载时机：主 Agent 准备启动审核 subagent **之前**（一次 Read 即可）。

---

## 1. subagent 类型

`general-purpose`

## 2. 输入

```
1. 草稿全文（从 .scheme/temp/<name>-draft-<yymmdd>.md 读取）
2. §Code Review Checklist 全文（作为审查清单，从主 SKILL.md 引用）
3. 本文件 §3 的行为约束（启动 subagent 时作为 prompt 附加）
```

## 3. 行为约束（传给 subagent 的 prompt 附加段）

- 只输出审核报告，**不要修改草稿、不要写新方案**
- 严格按 §4 模板输出，不要自由发挥、不要新增模板外的章节
- 风险等级**只能**使用 高 / 中 / 低
- 必须覆盖 §Code Review Checklist 的全部 11 项（背景 / 选型 / 设计 / 契约 / NFR / 可观测性 / 风险 / 数据迁移 / 回滚 / 估算 / 总览）
- 缺数据 / 缺章节时直接标 ❌ 并写入"缺失项清单"，**不要**替作者补内容

## 4. 审核报告模板（subagent 输出格式）

```markdown
# 审核报告：<方案标题>

> **审核对象**：.scheme/temp/<name>-draft-<yymmdd>.md
> **审核时间**：yyyy-mm-dd
> **审核者**：审核助手（subagent）

## 一、总评
- 结论：通过 / 需修改后重审 / 建议重写（三选一）
- 5 分钟扫读结论：<一句话>

## 5. 失败处理

| 场景 | 处理 |
|------|------|
| subagent 返回空 / 非结构化 | 主 Agent 重试 1 次，仍失败则报告用户并询问是否跳过审核 |
| 落盘失败 | 检查 `.scheme/temp/` 目录权限，提示用户 |
| 报告内容缺 §4 必填章节 | 视为非结构化，按上面第一条处理 |

## 6. 主 Agent 启动审核 subagent 的 prompt 模板

```
你是 solution-expert 的"审核助手"。

任务：对下面这份方案草稿按 §Code Review Checklist 11 项做严格审查，输出结构化审核报告。

=== 草稿全文 ===

=== 草稿结束 ===
