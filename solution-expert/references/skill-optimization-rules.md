# Skill 优化约束知识库

> 本文件由 `solution-expert` 在 §Step 1.0「Skill 优化前置」**按需**读取，**不要**在主 SKILL.md 中整段复述，也不要在启动时自动加载。
>
> 加载时机：主 Agent 命中"对 X skill 出优化方案"请求后，**一次 Read** 即可。
>
> 版本：v0.3.52（与 solution-expert 共用同一版本号，references/ 演进条款触发 §修改本 skill 的硬性约定 4 件事）

---

## 1. 使用约定

- **本知识库 ≠ SKILL.md**——只列硬约束与必查项，不复述工作流
- **本知识库 ≠ 决策树**——具体决策回到主 SKILL.md §Step 1.0「Skill 优化前置」表格
- **目标 skill 四档分类**（自身/同源/第三方/未在册）下，硬约束的命中方式不同——见 §3
- **回填建议**：发现新约束时登记到本文件 §2，并在 solution-expert §3.1 references/ 演进条款触发 §🔴 4 件事
- **不引入** 任何流程图、状态机、ADR 模板——本文件**只**是约束清单

---

## 2. 硬约束清单（按 C-N 编号）

### C-001 · frontmatter 必填校验

- **强制**：`name` + `description` 缺失即视为不可优化，必须先补
- **建议**：`metadata.version` 必填；`metadata.last_updated` 在每次实质修改后同步
- **触发**：所有四档分类
- **回退**：在方案中标注"待 frontmatter 补全"，不进入 §3 详细设计

### C-002 · 版本号递增策略

- **强制**：被修改的 skill 走 **末位 +1**（如 `0.3.51 → 0.3.52`）；跨大版本必须先讨论
- **强制**：frontmatter `version` 与正文启动确认行（如 `🎯 [skill vX.Y.Z]`）**两处必须一致**
- **触发**：自身 / 同源
- **回退**：若发现版本号不一致，停下报告用户，不得静默修复

### C-003 · 引用证据时间锚

- **强制**：所有行号引用配套 `commit SHA`（首选）/ `日期`（次选）/ `版本号`（退路）
- **禁止**：裸行号引用（如 `SKILL.md:187`）不带时间锚
- **触发**：所有四档分类
- **回退**：漂移即回到 §Step 1 重取证并更新调研证据台账

### C-004 · references/ 演进条款

- **强制**：被修改的 skill 若涉及 `references/*.md` 的非纯格式修改，必走 §修改本 skill 的硬性约定 4 件事（bump 版本号 + 追加 §4 修订记录 + 同步三处版本号 + 双处落盘）
- **强制**：references/ 与 SKILL.md **共用同一版本号**（v0.3.X 递增）
- **触发**：自身 / 同源
- **回退**：被忽略的 references/ 修改视为"修改未完成"，skill-iter 会拦截

### C-005 · 编辑源原则

- **强制**：唯一编辑源 = `solution-expert/` 工作副本（其他 skill 同理）；部署副本（`.claude/skills/<skill>/`）仅接收本轮清单的对应同步
- **禁止**：无清单整树覆盖部署副本
- **触发**：所有四档分类
- **回退**：若发现部署副本被独立编辑，停下报告用户并比对 diff

### C-006 · 章节编号稳定性

- **强制**：被修改的 skill 章节编号不得跳号或随意重排（如 §3 直跳 §5）
- **建议**：小节编号（### / ####）可以新增，但**不得删除既有 §N 标题**（如有废弃，应保留 + 标注"已废弃"）
- **触发**：所有四档分类
- **回退**：方案 §3.1 文件级影响清单必须列出"新增/修改/删除"三类，删除需独立标注

### C-007 · 自身修改必须走 4 件事

- **强制**：目标 skill = solution-expert 自身时，**必走** §修改本 skill 的硬性约定 4 件事
  1. 先 `Read references/maintenance.md` + `SKILL.md`
  2. 改完后追加一行到 `maintenance.md §4 修订记录`
  3. 同步更新 frontmatter `version` / `last_updated` / 启动确认行三处
  4. 双处落盘（工作副本 + 部署副本）+ 逐文件 `diff` 校验
- **触发**：自身（solution-expert）
- **回退**：任何一项缺失即视为"修改未完成"

### C-008 · 命名隔离（避免与评审报告/审核报告混淆）

- **强制**：skill 优化方案落盘到 `.scheme/<name>-<yymmdd>.md`
- **强制**：用户走"评审模式"产出评审报告到 `.scheme/review/`
- **禁止**：skill 优化方案误用 `.scheme/review/` 目录
- **触发**：所有四档分类
- **回退**：错放目录即停下报告用户，请用户裁决

### C-009 · 知识库膨胀红线

- **强制**：本文件行数 ≤ 200 行；超过即拆为 `references/skill-optimization-rules/` 子目录
- **强制**：硬约束清单只列"做什么 / 触发条件 / 回退"，**不**展开"为什么 / 怎么展开"
- **触发**：所有四档分类（约束本知识库自身）
- **回退**：`wc -l references/skill-optimization-rules.md` 校验；超 200 行触发 §修改本 skill 的硬性约定 走拆目录方案

### C-010 · 未在册 skill 知识盲区处理

- **强制**：用户给的 skill 路径不在 §跨 skill 协作 表（solution-expert SKILL.md 内）中时，先 `Read` 该 skill 的 `SKILL.md` frontmatter + 最近 5 个 commit
- **禁止**：凭路径名猜测 skill 用途或直接套用其他 skill 的硬约定
- **触发**：未在册
- **回退**：Read 失败即不进入"按需加载"前置，退回 §入口分流 原有 4 路径分支

## 4. 失败处理

| 场景 | 处理 |
|------|------|
| 本文件缺失 | 降级到 §Step 1 默认流程（不阻塞 Step 1-4），wc -l 报警；提示用户补全 |
| 硬约束 C-N 与 solution-expert §修改本 skill 的硬性约定 冲突 | 以 solution-expert §修改本 skill 的硬性约定 为准（硬性 4 件事凌驾一切） |
| 同一 skill 在同一会话被多次优化 | 第二次起合并到首次的方案文档，不另起文件（避免 `.scheme/` 碎片化） |
| 用户要求"跳过知识库" | 显式登记"用户已 opt-out"，但 C-007（自身 4 件事）**不可**跳过——属硬性 4 件事范畴 |
