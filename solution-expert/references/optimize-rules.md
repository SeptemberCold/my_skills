# 优化助手契约

> 本文件由 `solution-expert` 在 Step 4.3 **按需**读取，**不要**在主 SKILL.md 中整段复述。
>
> 加载时机：主 Agent 准备启动优化 subagent **之前**（一次 Read 即可）。

---

## 1. subagent 类型

`general-purpose`

## 2. 输入

```
1. 草稿全文（.scheme/temp/<name>-draft-<yymmdd>.md）
2. 审核报告全文（.scheme/temp/<name>-review-<yymmdd>.md）
3. 本文件 §3 的行为约束（启动 subagent 时作为 prompt 附加）
```

## 3. 行为约束（传给 subagent 的 prompt 附加段）

- 对审核报告的每条建议逐条判断：**采纳 / 部分采纳 / 不采纳**
- **不采纳必须给出理由**（一句话即可）
- **不引入**审核报告没建议的新需求、新章节、新增字段（避免范围蔓延）
- 保留审核报告"亮点"清单中点出的好内容，**不要为改而改**
- 修改前先在内部"修改追溯表"登记，再写正文
- 最终方案保留原 8 章结构，**只在 §8 附录追加"修改追溯表"**，不要重排章节号
- 不修改 frontmatter / 文档元信息（这些是模板决定的）

## 4. 修改追溯表模板（作为最终方案 §8 附录）

```markdown
## 附录：基于审核报告的修改追溯

| # | 审核建议 | 处理 | 落地位置 | 备注 |
|---|---------|------|---------|------|
| 1 | 补 NFR 量化 | ✅ 采纳 | §1.4 表格新增 2 行 | 原缺失"容量"维度 |
| 2 | 改 Redis 单点为 Cluster | ⚠️ 部分采纳 | §4 风险表 | Cluster 成本评估中，暂记风险 |
| 3 | 增加 §X 章节 | ❌ 不采纳 | — | 与现有 §Y 重复，合并即可 |
```

## 5. 失败处理

| 场景 | 处理 |
|------|------|
| subagent 返回空 | 主 Agent 重试 1 次，仍失败则保留草稿并询问用户 |
| 追溯表与审核报告对不上（数量、编号错位） | 触发"修改追溯表不一致"告警，请用户裁决 |
| 优化结果与草稿差异过大（> 80% 内容被重写） | 主 Agent 报告差异并请用户确认 |
| 用户在审核后想直接采纳审核意见、不走优化 | 收尾步骤提供"采纳审核意见并停止"快捷选项，跳过 subagent |

=== 草稿结束 ===

=== 审核报告全文 ===
<在此粘贴审核报告全文>
=== 审核报告结束 ===

- 不采纳必须给理由
- 不引入审核没建议的新内容（避免范围蔓延）
- 保留审核"亮点"清单的好内容
- 修改前先在内部"修改追溯表"登记
